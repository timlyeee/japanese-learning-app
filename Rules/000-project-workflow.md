# 工作流程与交付

## 需求处理流程

每个需求按以下顺序执行，不跳步：

1. 沟通需求：与用户确认目标、范围与约束，消除歧义。
2. 写功能文档：在 `Docs/` 新建或修改对应功能文档，记录需求、现状、设计与验证点。
3. 落地代码：按功能文档实现。
4. 反查纠错：实现后回头核对功能文档，改正与代码不符的描述。
5. 再检查：运行对应验证（`npm run check` / `npm test` / `npm run build`），确认无类型错误与回归。
6. 完成：向用户总结变更、验证结果与未决事项。

功能文档在 `Docs/`，规则在 `Rules/`，两者分开。功能文档描述「某个功能要做什么、现状、设计」；规则描述「怎么工作」。永远保持最新功能，而不记录过程中的历史记录。

- 与用户用中文沟通，说明具体结果、验证与尚未确认的限制。
- 先检查 Git 状态，保留用户修改；不要覆盖已有学习进度或凭据。
- 本项目使用 npm 和 package-lock.json，安装后保持锁文件同步。
- 开发使用 `npm run dev`；正式网页使用 `npm run build` 后 `npm start`。本机页面地址为 `http://127.0.0.1:3000`。
- TypeScript 变更运行 `npm run check`；复习算法、题目生成、存储迁移和 API 合约变更运行 `npm test`；页面或打包变更运行 `npm run build`。
- 页面布局变更检查手机宽度和实际交互。区分网页验证、APK 编译验证与真机验证，不把编译成功写成真机通过。
- 使用 `npm run format` / `npm run format:check` 统一格式。
- 长期说明更新 README 或对应规则；不要新增互相矛盾的说明副本。
- 不提交 `.env`、真实密钥、签名文件、个人 SDK 路径、依赖缓存、构建输出和学习进度备份。
- 上传仓库、发布和安装设备依用户授权范围执行，不从普通代码修改推断发布授权。
